## Features by area

### Pointer harness: cluster answers and patterns (with `--pir-harness`)

| Flag | One-line meaning |
|---|---|
| `--pir-container-of` | A parameter used at a negative constant offset gets its containing object (container_of / accessor harness). |
| `--pir-field-invariants FILE` | Value invariants of struct fields (valid, nonnull, range), with scope and minimisation to the rows used. |
| `--pir-addr-values` | Constant `ptrtoint` / `inttoptr` and integer-address initialisers are modelled as named assumptions. |
| `--pir-harness-deep` | Depth 4 and 64 objects per parameter; what the bound cut is recorded. |
| `--pir-length-pairing` | A pointer indexed under a bound by an integer parameter (also through library calls with a length) is sized from that parameter; type alignment of the objects. |
| `--pir-declared-types` | A harness pointee is sized by its declared type (debug info) and preferred over IR evidence; never below the largest struct it is used as at offset 0. |
| `--pir-priv-areas` | A struct at the end of a harness object (`netdev_priv` style) sizes the object to its end. |
| `--pir-index-field-bounds` | An integer field that indexes an in-object array is assumed in `[0, N-1]`. |
| `--pir-heap-freed` | A harness object passed to `kfree` / `free` is a live heap allocation. |
| `--pir-param-preconditions FILE` | Per-parameter preconditions (`valid N`, `type S`, `nonnull`, `range A B`) from a TSV; each used row is a named assumption. |
| `--pir-callback-models FILE` | Driver callback preconditions adapted from Klever (Apache-2.0), including `drvdata` (probe ran first) ([DRIVER_ENV_MODELS.md](DRIVER_ENV_MODELS.md)). |
| `--pir-discharge`, `--pir-discharge-closure`, `--pir-discharge-out FILE`, `--pir-obligations FILE` | Call-site discharge: the invented harness is checked at every call site, up the call graph, and across units with `prism-qa callsite-discharge` ([HARNESS_GENERATOR.md](HARNESS_GENERATOR.md)). |
| `--pir-vacuity` | A harnessed function whose exit is unreachable is NEEDS-HARNESS, never a proof. |

Harness objects whose size came from the access are tagged (harness-size-from-access, container-type-from-cast) so a
violation resting on them is never FAILED; the declared type is preferred over the access size.

### Kernel mode (with `--kernel-api`)

| Flag | One-line meaning |
|---|---|
| `--pir-build-semantics` | A unit built with `-fwrapv` / `-fno-strict-overflow` is lowered and checked with wrapping signed arithmetic. |
| `--pir-kernel-stops` | `BUG()`, `panic`, `kassert_panic` end the path like `exit`. |
| `--pir-kernel-current` | The running thread (`current`, `curthread`) exists. |
| `--pir-global-harness`, `--pir-global-harness-deep` | A mutable pointer global points at a valid object at entry; the deep variant also harnesses the pointer fields it loads. |
| `--pir-lock-wrappers` | Functions that only acquire (or only release) locks are treated as lock wrappers by the lock-order pass. |
| `--pir-lock-scopes` | Lock-order classes follow zero-offset GEPs and argument-returning helpers ([KERNEL_CONCURRENCY.md](KERNEL_CONCURRENCY.md) section 17). |
| `--pir-bpf-helpers` | A BPF helper's `ARG_PTR_TO_*` arguments are harnessed from its `bpf_func_proto`. |
| `--pir-icall-havoc` | An unresolvable indirect call is one execution of an arbitrary function (everything havocked). |
| `--pir-builtin-contracts` | Contracts for `llvm.read_register`, `llvm.prefetch`, `llvm.objectsize`. |
| `--lock-contracts FILE` | Lock contracts for unmodified kernel code; the markers need `--kernel-api` (fix below). |

### Unencoded wave 2 (each a named assumption or an over-approximation)

| Flag | One-line meaning |
|---|---|
| `--pir-variadic` | `va_start` / `va_arg` over fresh arbitrary objects instead of UNENCODED. |
| `--pir-recursion` | A recursive call is assumed violation-free (induction hypothesis on the call depth). |
| `--pir-kernel-sprintf` | `sprintf` with a literal format writes a sound bound of characters (kernel `%p` extensions included). |
| `--pir-addrspace` | `addrspace(N)` accesses (per-CPU `%gs` / `%fs`) are ordinary pointer accesses. |
| `--pir-wide-int` | 65 to 512 bit integers (`__int128`, bitfield containers) are bit-vectors of their width. |

### Front end, input and targets

| Setting | One-line meaning |
|---|---|
| `--pir-input-hash` | Translate only; each row is NOTRUN with `input_key` and `input_key_loc_free`, the SHA-256 of everything the verdict is computed from. |
| `--pir-header-fns` | A function defined in a header is checked in a stub unit named by `PRISM_PIR_ONLY` (lowered with `-femit-all-decls`). |
| False-globals reclassification | A `FAILED` whose violation needs other values of the mutable globals than their initialisers is NEEDS-HARNESS; two re-checks with only the globals fixed to the initialisers, so the change only weakens a verdict (`extra.globals`, `extra.globals_involved`; [PIR.md](PIR.md), global state). |
| Non-LP64 targets | A unit built for ILP32 (or any target that is not LP64 little-endian) is NOTRUN, never checked as x86-64. A stopgap; see [NEXT_WEEK.md](NEXT_WEEK.md). |
| Big-endian targets | NOTRUN with one row that says so (the memory model assembles values little-endian). |
| Law 6 for integers used as pointers | An integer parameter that is cast to a pointer and dereferenced is NEEDS-HARNESS, like a pointer parameter. |

### Solvers and loop proofs

| Setting | One-line meaning |
|---|---|
| `PRISM_CUBE=1` (+ `PRISM_CUBE_*`) | Cube-and-conquer member (CPU and GPU) for queries the portfolio has not answered; the UNSAT path is recorded as `unsat_by` = `tree`, `root_unsat` or `empty_clause` ([SOLVERS.md](SOLVERS.md)). |
| `PRISM_PIR_CHC=1 / data / only`, `PRISM_PIR_LOOP_CANDIDATES=FILE` | Spacer/CHC loop proofs after the Houdini template search; every lemma is re-checked by Houdini's own queries ([PIR.md](PIR.md) "Loop proofs by CHC"). |

## Soundness fixes this week

- **#64**: the csmith shift wrong proof is fixed.
- The folded-UB owner is decided by source span, and only for functions of the main file; a header function never inherits the unit's folded-UB rules.
- Lock-contract markers need `--kernel-api`; without it they are not applied.
- Access-sized harness objects are tagged, and declared types are preferred, so a violation resting on an invented size is NEEDS-HARNESS.
- Test-only fixes: the `prism-module` environment leak in tests and the e2e use-after-free (tests run in one process again).
- The pool packing issue behind the single G6 failure.
