# DO-333 (formal methods supplement) mapping

RTCA DO-333 supplements DO-178C when formal methods are used as a
verification technique. It adds formal-analysis objectives to the DO-178C
Annex A tables (published as the FM.A-x tables) and replaces or supplements
some review, analysis and coverage objectives when formal analysis is used.
This document maps the evidence in this repository to those objectives.
Evidence identifiers (E01...) are defined in [EVIDENCE.md](EVIDENCE.md).

Read [README.md](README.md) first. In short: this is a mapping aid, not a
compliance claim; objective titles and section numbers are as commonly
cited and must be checked against the licensed RTCA text, which is not in
this repository.

## How PRISM would be used under DO-333

PRISM analyses C and C++ source code (and, in the `pir` stage, the LLVM IR
clang produces from it) for a fixed set of properties: signed overflow,
division by zero, shift range, the other poison conditions of the IR,
reachability of `assert` failures and `abort`, and, in the `bmc` stage,
bounds of constant-size local and global arrays
(`docs/PIR.md#properties-inserted-by-prism-law-8`,
`docs/USER_GUIDE.md#verdicts`). Preconditions are written as
`// requires:` lines (`harness` stage) and ACSL-style `requires` / `ensures`
annotations are read by the `contracts` stage. The C++ `pir` stage has a
memory model (`docs/PIR.md#memory-model-roadmap-25`): null, wild and
dangling dereference, out-of-bounds access, misalignment, invalid, double
and mismatched free and pointer arithmetic are checked properties, encoded
by default as QF_BV read-over-write chains in the design of the Lean memory
model (E05); the C++ is not proved to implement that model. Constructs it
does not encode are named and `NEEDS-HARNESS`
(`docs/PIR.md#what-is-not-encoded-named-never-dropped--roadmap-21`). An applicant would use its `PROVED*`
verdicts as formal analysis of the **Source Code** for those properties,
and its `FAILED` verdicts (with a replayed counterexample) as findings.
PRISM does not formalise high-level or low-level requirements, does not
analyse architecture or design models, and does not analyse executable
object code.

Status words used below: **Evidence** (an artefact supports the objective
for the scope stated), **Partial** (supports part of it; the gap is named),
**Not addressed**.

## Tool qualification

A PRISM verdict used to eliminate, reduce or automate a DO-178C
verification activity makes PRISM a verification tool that needs
qualification under DO-330. That analysis is in [DO-330.md](DO-330.md).
PRISM is not qualified.
